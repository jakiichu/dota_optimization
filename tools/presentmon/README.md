# PresentMon

Сюда кладётся `PresentMon.exe` — консольная версия трассировщика кадров от Intel.
В git бинарник не попадает: репозиторий не место для чужих сборок.

## Как получить

Скачать **PresentMon-<версия>-x64.exe** (не `.msi` — тот весит 150 МБ и тянет
за собой графическую оболочку) со страницы релизов и переименовать в
`PresentMon.exe`:

<https://github.com/GameTechDev/PresentMon/releases>

Проверено на версии, которую стоит считать эталонной:

| | |
| --- | --- |
| Версия | 2.5.1 |
| Файл | `PresentMon-2.5.1-x64.exe` (956 768 байт) |
| SHA-256 | `9bec3083069f58f911e6a512f4806db51a27bd096103087bc1d05ef54c80a191` |
| Подпись | `CN=Intel Corporation` — статус `Valid` |
| Лицензия | MIT |

Проверить подпись перед использованием:

```powershell
Get-AuthenticodeSignature .\tools\presentmon\PresentMon.exe | Format-List Status, SignerCertificate
```

## Почему нужны права администратора

PresentMon читает события ETW от `Microsoft-Windows-DxgKrnl`, а сессии трассировки
ядра требуют повышения. Без него он завершается с кодом **6** — приложение ловит
именно этот код и перезапускает запись через UAC.

Чтобы запроса UAC не было вовсе, запускайте `npm run capture` из терминала,
уже открытого от имени администратора.

## Почему не свой сборщик ETW

Разбор презентов — это state-машина поверх событий DXGI, DxgKrnl и композитора,
которую Intel отлаживает не первый год. Переписать её с нуля можно, но это недели
работы ради худшего результата, чем готовый инструмент под MIT.

Границы при этом соблюдены: PresentMon читает ETW пассивно, не внедряется в
процесс игры и не трогает её память — то есть не создаёт проблем с античитами.
