# Кадроскоп

Диагностика времени кадров и статтеров в Dota 2 на Windows: аудит настроек,
запись кадров, анализ причин и сравнение результатов изменения конфигурации.

## Запуск из исходников

Требуется Node.js с поддержкой запуска TypeScript без компиляции
(проект запускается командой `node src/main/server.ts`).
Установите зависимости через `npm ci`, затем выполните `npm start`.
Откроется настольное окно Electron. Веб-режим для разработки доступен через `npm run start:web`.
Подробности сборки, получения PresentMon и настройки .NET-сайдкара — в
[CLAUDE.md](CLAUDE.md) и [инструкции PresentMon](tools/presentmon/README.md).

## Настольное приложение и трей

`npm run desktop:release` создаёт Windows-сборку в новой подпапке `release/desktop-*`.
Откройте `Кадроскоп.exe` двойным щелчком: браузер и консоль не нужны.
Передавайте всю папку сборки. Node.js и .NET на целевой машине не требуются.

- Крестик скрывает окно в трей; запись продолжает работать.
- Двойной щелчок по значку возвращает окно. Повторный запуск exe открывает существующий экземпляр.
- Меню значка: открыть, записать 60 секунд, остановить и сохранить, выйти.
- Красная отметка на значке обозначает активную запись или подготовку к ней.
- При выходе во время записи можно продолжить её либо остановить, сохранить и выйти.
  Если остановка или сохранение не удались, приложение остаётся открытым.
- Скрытый мониторинг не обновляет графики; сенсоры для самой записи продолжают собираться сервером.

В готовой сборке записи лежат в `%APPDATA%/Кадроскоп/sessions`, журнал запуска —
в `%APPDATA%/Кадроскоп/desktop.log`. В режиме разработки сохраняется прежняя папка
`sessions` в проекте. Для переноса старых записей скопируйте их в новую папку
при закрытых экземплярах приложения. Обновление сборки не удаляет архив.

Автозапуск с Windows и автоматическая запись при старте Dota в эту версию не входят.
Запрос прав Windows для PresentMon при записи и остановке остаётся.

## Проверка одной настройки

Во время записи над разделами видна общая панель со статусом и кнопкой
«Остановить». Можно переходить между разделами и обновлять страницу:
интерфейс подхватит статус с работающего сервера, а после завершения покажет,
что запись сохранена. Закрытие самого приложения или перезапуск сервера
этот механизм не покрывает. Пятисекундное ожидание перед стартом переживает
переход между разделами; обновление страницы до начала записи отменяет ожидание.

Для проверки рекомендации из готовой записи нажмите «Проверить по шагам» в
блоке «Что попробовать». Приложение сохранит исходную запись как основу
проверки и откроет предложенные изменения черновиком в конфиге.
Панель «Проверка настройки» над разделами показывает следующий шаг и позволяет
выбрать повторную запись для проверки результата. Сохранённая гипотеза доступна
и после перезапуска приложения. Черновик конфига сохраняется при переходах
между разделами, но не после перезагрузки страницы.

В панели предлагаются совместимые записи, сделанные после начала проверки.
Остальные записи можно разобрать в разделе «Сравнение».
Приложение подтверждает значения в файле, но не их применение в запущенной игре.

Для проверки устойчивости результата используйте серию:

1. В «Записи и разборе» выберите повтор и начальный тик. Запишите один участок
   три раза с одинаковой длительностью. Подпишите записи «до 1», «до 2», «до 3».
2. Измените одну настройку в «Настройках Dota», сохраните и примените её в игре.
   Сохранение файла само по себе не подтверждает, что игра применила настройку.
3. Повторите тот же участок ещё три раза: «после 1», «после 2», «после 3».
   Сохраняйте камеру, момент старта записи и фоновые программы.
4. Откройте «Сравнение → Повторные замеры» и выберите шесть записей.
   Результат появится после заполнения всех полей.

Серия показывает медианы и диапазоны отдельных прогонов. Повторившийся эффект
требует одинакового направления во всех парах и непересекающихся диапазонов
хотя бы одной основной метрики. Противоположные изменения отмечаются как
смешанный эффект. Разные сцены, приложения, длительности с разницей больше 10%
или изменения настроек внутри группы блокируют общий вывод.

Диапазон — минимум и максимум выбранных прогонов, не доверительный интервал.
Результат описывает эти записи и сам по себе не доказывает причину изменения.
Начальный тик — сохранённое условие прогона; фактическую синхронизацию записи
и камеру нужно выдерживать самостоятельно.

Обычное сравнение двух записей доступно в режиме «Две записи». Его фиксированные
пороги отсекают малые изменения, но не измеряют естественный разброс.

## Разбор отдельного рывка

Откройте сохранённую запись и выберите один из самых длинных кадров в блоке
«Разбор отдельного рывка». Приложение приблизит участок в полторы секунды до и
после события, отметит выбранный кадр на графике и покажет его длительность,
локальную норму и совпавшие события. В список входят и рывки без найденных улик.
Если анализ всей записи уже сформировал подходящую проверку, инспектор показывает
её ожидаемый результат и ведёт к полной карточке рекомендации.

Совпадение нагрузки или ожидания с рывком помогает выбрать следующую проверку,
но само по себе не доказывает причину.

## Отчёт для отправки

Откройте сохранённую запись в разделе «Запись и разбор» и нажмите
«Подготовить отчёт». В предпросмотре можно включить график времени кадра
и показатели задержки ввода, затем сохранить один HTML-файл на рабочий стол.
Файл открывается без интернета; его также можно распечатать из браузера.

В отчёт входят показатели всей записи, до 12 самых длинных статтеров,
краткая интерпретация узкого места и ограничения выводов. Подпись записи,
имя компьютера, пути, идентификаторы, список программ и конфиг не экспортируются.
Это краткий отчёт, а не архив исходной телеметрии для повторного анализа.

## Перенос управления между Steam-аккаунтами

В разделе «Настройки Dota» выберите источник и получателя в блоке «Перенос управления
между аккаунтами». Приложение копирует только персональную раскладку Dota из
`dotakeys_personal.lst`: чат, сетки героев, косметика и прочее состояние
аккаунта не затрагиваются.

Перед записью показывается точное направление переноса. Если у получателя уже
есть раскладка, прежний файл сохраняется рядом с отметкой времени и расширением
`.bak`. Dota должна быть закрыта, иначе Steam Cloud может вернуть версию файла,
которую игра сохранила при выходе.

## Проверки разработки

`npm run check` проверяет типы, границы архитектуры и тесты.
`npm run ui:build` собирает интерфейс.

## Проверка ресурсов в обзоре системы

Блок «Что можно улучшить» показывает доступную оперативную память, свободное
место на дисках Windows и Dota, а также среднюю нагрузку других программ за
интервал не короче 15 секунд. Для обновления нажмите «Проверить заново».
Процессы одного приложения объединяются, Dota исключается из списка нагрузки.
Недоступные и недавно запущенные процессы могут отсутствовать в замере.

Пороги памяти (меньше 2 ГБ и 15%) и диска (меньше 10 ГБ или 10%) — ориентиры
для проверки, не доказательство причины рывков. Рекомендации не меняют настройки
и не завершают программы. Результат изменения проверяйте сравнением записей.
Старые снимки без данных ресурсов показывают «Не удалось проверить».
